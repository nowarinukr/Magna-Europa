# Перший запуск 1.19.4: темна карта та виліт

## Спостереження

Користувач надав `setup.log`, `system.log`, `error.log`, `game.log`, `meta.yml` та `exception.txt`. За журналами це **Operation Postern v1.19.4.1.99a5**, DirectX 11, увімкнено лише `Great Bruh V2 - 1.19.4 TEST`, запускається нова кампанія 1911 року. Користувач уточнив, що успішна гра в оригінальний мод відбувалася на **старішій** версії HOI4. Необроблені журнали, локальні шляхи та системні ідентифікатори не включено до репозиторію.

У `error.log` є **73 помилки компіляції шейдерів** і відповідні повідомлення про невдале додавання піксельних шейдерів. Усі помилки компіляції називають один відсутній символ:

```text
error X3004: undeclared identifier 'MUD_CAM_MIN'
Failed adding pixel shader gfx/FX/pdxmap.shader(...)
```

Зачеплено 17 різних шляхів шейдерів, зокрема карту, воду, кордони, дерева, моделі й постобробку. Це сильне пояснення темної карти. Водночас `exception.txt` містить лише access violation з нерозшифрованим стеком; він не встановлює, який файл спричинив виліт після натискання «Почати».

## Виправлення для наступного тесту

Єдина підміна шейдерів у моді — `gfx/FX/constants.fxh`. Вона має старі параметри бруду та снігу, але не містить `MUD_CAM_MIN`. Її вміст не змінювався від первісного коміту `c42e981`, тобто це несумісність вихідного моду з новою грою.

Файл перенесено без зміни байтів у `docs/legacy-graphics/constants.fxh`, поза активною графічною папкою. Тепер рушій має використати **свій власний актуальний** `gfx/FX/constants.fxh`. У жодному описувачі немає `replace_path` для `gfx` або `gfx/FX`, а інших підмін шейдерів у моді немає. Значення відсутніх констант не вигадувалися.

Це діагностичне виправлення. Воно зберігає файли географії та масштаб у Lua, але повертає базові налаштування освітлення, текстурування, снігу, води, туману та вигляду кордонів. Авторський вигляд можна відновлювати окремо після порівняння з актуальним ванільним `constants.fxh`. Резервна копія оригіналу та історія Git залишаються доступними.

## Повторне встановлення вручну скопійованої тестової версії

`Pull origin` оновлює репозиторій на комп'ютері, але **не оновлює автоматично** окрему копію в `Документи/Paradox Interactive/Hearts of Iron IV/mod`.

Для цього виправлення, коли гру та лаунчер закрито, потрібно перенести **за межі тестового моду** старий файл:

```text
Документи/Paradox Interactive/Hearts of Iron IV/mod/great_bruh_1194_test/gfx/FX/constants.fxh
```

Наприклад, зберегти його на Робочому столі. Інші файли не потребують заміни для цього конкретного тесту. Не змінювати однойменний файл у встановленій базовій грі.

Після цього знову запустити лише тестовий мод і окремо зафіксувати:

1. Чи відображається карта на екрані вибору країни?
2. Чи завантажується нова кампанія 1911 року?
3. Чи повторюються `MUD_CAM_MIN` / `Failed adding pixel shader` у свіжому `error.log`?

Надіслати свіжі `error.log`, `game.log` і, якщо гра знову впаде, новий `exception.txt`. Повторний запуск рушія тут недоступний; зміна ще потребує перевірки на комп'ютері користувача.

## Інші виявлені несумісності

Є повідомлення про відсутні технології, категорії, scripted effects/triggers, невідомі токени й порожні таблиці погоди стратегічних регіонів. Частина нових ванільних систем (`doctrines`, `special_projects`, `factions`, `focus_inlay_windows`) посилається на вміст, який старий мод повністю замінює. Це окремі завдання адаптації, але журнали не доводять, що конкретно одне з цих повідомлень спричинило цей виліт. Їх не приховували вимкненням підсистем навмання.

Три названі користувачем DLC не встановлені як причина збою. Перший наступний тест перевіряє підміну шейдерів без змін DLC, драйвера чи налаштувань графіки, щоб не змішувати причини.
