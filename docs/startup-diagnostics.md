# Діагностика вильоту після «Почати»

## Підтверджені результати

- Прибирання старого `gfx/FX/constants.fxh` виправило темну карту за підтвердженням користувача; у нових журналах немає шейдерних помилок.
- Оновлення будівель і категорій зменшило повідомлення про будівлі 35 → 0, невизначені категорії підрозділів 129 → 0, unexpected tokens 219 → 83. Виліт на старті залишився.
- Однофайловий тест без установленого `interface/countryproductionlineview.gui` не усунув виліт. Нові журнали мають новий час, але після нормалізації часу `error.log` точно повторює попередній вміст. Стек теж залишився тим самим. Цей тест не дає підстав залишати вікно вимкненим: його слід повернути перед наступним дослідом.
- Нерозшифрований стек не встановлює конкретного винуватця. Останні повідомлення `error.log` з'являються ще до завантаження історії; вони не є доказом причини вильоту.

## Чому не міняємо рівні досвіду навмання

П'ять порогів `UNIT_EXP_LEVELS` у моді відрізняються від чотирьох у наданій базовій грі. Однак `interface/replace/gbruh.gfx` також визначає шість кадрів `GFX_unit_level`. Отже, розширена система виглядає авторським задумом, а вимоги фіксованої довжини в наданих defines немає. Це можливий окремий контрольний тест, але не доведений дефект. Значення досвіду на цьому етапі не змінювалися.

## Позначки етапів

Додано тільки діагностичні `log` у два наявні ефекти:

| Позначки в `game.log` | Що вони можуть підтвердити |
| --- | --- |
| `MAGNA_DIAG_BOOKMARK_WEATHER_BEGIN` / `END` | Виконання дійшло до та пройшло `randomize_weather` стартового сценарію |
| `MAGNA_DIAG_STARTUP_BEGIN` / `END` | Виконання дійшло до та пройшло існуючий ефект `on_startup` для австрійських держав |

Оригінальні ефекти, їхній порядок усередині блоків, seed погоди, дати та налаштування досвіду збережені. Немає залежності від алфавітного порядку виконання різних файлів.

Обидві позначки означають проходження відповідного блоку, але не гарантують успішного завершення решти запуску. Тільки BEGIN звужує ділянку для перевірки з урахуванням буферизації журналу. Відсутність позначок сама по собі не доводить, де стався збій: dispatch міг ще не відбутися, буфер міг не записатися або встановлена копія могла залишитися старою.

Для наступного запуску варто ввімкнути `-debug` у параметрах запуску Steam та зберегти свіжі журнали. Після `Pull origin` потрібно замінити у **встановленій** тестовій копії відповідні файли `common/bookmarks/the_gathering_storm.txt` і `common/on_actions/bruh_on_actions.txt`; саме оновлення репозиторію не змінює встановлену копію.

Це інструментування, а не виправлення причини вильоту. Його виконання рушієм тут не перевірено.

## Погода: підтверджена нестача даних, непідтверджена причина вильоту

Усі **251** активні файли `map/strategicregions/*.txt` містять порожній `weather={}`. Новий журнал має рівно **251** попередження, що річне покриття температур закінчується на `0.0` замість `30.11`.

Перед перенесенням цих даних потрібен **один актуальний ванільний файл** із `map/strategicregions` гри 1.19.4 зі заповненим блоком погоди. За ним можна перевірити формат, а потім підготувати окрему перевірку річного покриття. Не слід підставляти довільні температури й імовірності для всіх географічних зон або проголошувати, що саме порожня погода спричинила цей виліт.
