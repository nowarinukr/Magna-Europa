# Будівлі, категорії військ та script enums для 1.19.4

## Підстава змін

Після усунення старої підміни шейдерів користувач підтвердив видиму карту. У журналах наступного запуску за Німеччину немає `MUD_CAM_MIN` або помилок компіляції шейдерів, але зберігається виліт відразу після старту нової кампанії. Нерозшифрований стек access violation не встановлює його причини.

Окремо підтверджено **35 відхилених параметрів** у старому `common/buildings/00_buildings.txt` та помилки категорій військ/переліків типів. Користувач надав відповідні три файли своєї базової гри 1.19.4; зміни нижче ґрунтуються на їхньому форматі. Вони виправляють конкретні дефекти завантаження даних; усунення вильоту ще потребує перевірки рушієм.

## Будівлі

- Для всіх 16 старих будівель `max_level` перенесено в `level_cap.state_max` або `level_cap.province_max` відповідно до попереднього `provincial`. `shares_slots` також перенесено в `level_cap`.
- Збережено всі 16 числових лімітів, поділ на регіональні/провінційні будівлі, правила спільних слотів та 134 інші значення полів, зокрема вартості будівництва й переобладнання. Серед збережених авторських значень — ліміти 5000 для фабрик і заводів.
- Два `max_fuel_building` і один `nuclear_production_factor` перенесено без зміни значень у `country_modifiers.modifiers`, як у наданій ванільній версії.
- Додано 17 відсутніх типів будівель, які є у наданому файлі гри, і всі шість визначень `spawn_points`. Для старих порту, ракетної бази та реактора додано відповідні підтверджені `spawn_point`. Загалом файл містить 33 типи будівель.
- Додані ванільні визначення збережені структурно без змін. Наявність визначення будівлі не означає, що для сценарію 1911 року вже перенесено її технології, проєкти чи баланс.

**Незавершена економіка:** чотири старі параметри утримання ресурсів поки не мають підтвердженої заміни у наданому файлі. Вони збережені в явних TODO-коментарях, а не перенесені у вигадані модифікатори:

| Будівля | Тимчасово неактивне старе поле | Значення |
| --- | --- | --- |
| `arms_factory` | `country_resource_cost_tungsten` | 1 |
| `arms_factory` | `country_resource_cost_aluminium` | 1 |
| `industrial_complex` | `country_resource_cost_aluminium` | 1 |
| `supply_node` | `country_resource_cost_aluminium` | 5 |

Це змінює ресурсну модель моду. Системи дефіциту й економічний баланс не можна вважати завершеними, навіть якщо наступний запуск буде успішним. Значення виробництва ресурсів (`local_resources_*`) залишені авторськими; відновлення витрат потребує окремого підтвердженого механізму 1.19.4.

## Категорії та переліки типів

- `sub_unit_categories`: **19 → 49**, відновлено всі 30 відсутніх категорій із базової гри.
- `script_enum_equipment_stat`: **71 → 78**. Додано вісім актуальних типів; старий `railway_gun_attack_range` прибрано після перевірки відсутності його активного використання у скриптах моду. У поточному переліку є ванільний `railway_gun_attack_range_index_in_define`.
- `script_enum_equipment_category`: **31 → 38**.
- `script_enum_equipment_bonus_type`: **435 записів із дублікатом → 532 унікальні**. Збережено всі 495 ванільних значень і всі 37 авторських доповнень; прибрано другий `ship_hull_heavy_1`.
- Інші три групи переліків не змінені за вмістом. Разом у шести групах 666 унікальних елементів.

Усі значення з наданих ванільних переліків збережено. Окремо перевірено 119 посилань на категорії у файлах підрозділів моду — невизначених категорій немає.

Наявність імені в enum **не створює** технологію або спорядження в базі гри. Наприклад, деякі старі ідеї досі посилаються на `fighter_equipment`, `scout_plane_equipment` та `cv_fighter_equipment`, яких немає у наданому ванільному enum. Штучні псевдоніми для них не додавалися. Залишаються й інші помилки нових ванільних підсистем, які звертаються до замінених модом технологій, ефектів та ідей.

## Перевірки

З кореня репозиторію, Python 3.10+:

```sh
python3 tools/check_buildings.py
python3 tools/check_enums.py --vanilla-categories /path/to/game/common/unit_tags/00_categories.txt --vanilla-enums /path/to/game/common/script_enums.txt
python3 tools/validate_mod.py
python3 -m unittest discover -s tests -v
git diff --check
```

Результат: **36 тестів пройшли**; перевірки будівель і enum/category — **0 помилок**. Загальний статичний валідатор — 0 помилок і одне відоме попередження `armored_car_recon`. У первісному файлі перевірка будівель знаходить 51 проблему: 35 застарілих полів і 16 відсутніх `level_cap`. Це рахунок статичного валідатора, а не кількість повідомлень рушія після виправлення.

Додаткове порівняння з Git перевірило всі збережені старі значення та місткість, точну структуру 17 доданих ванільних будівель і шести `spawn_points`. Повторного запуску HOI4 в цьому середовищі немає.

## Як отримати та встановити цю зміну

У GitHub Desktop у гілці `codex/hoi4-1.19.4-test`: `Fetch origin` → `Pull origin`, потім `Repository → Show in Explorer`.

У встановленій тестовій копії `Документи/Paradox Interactive/Hearts of Iron IV/mod/great_bruh_1194_test` замінити **три файли** відповідними файлами з оновленого репозиторію:

```text
common/buildings/00_buildings.txt
common/unit_tags/00_categories.txt
common/script_enums.txt
```

Потрібні саме змінені файли репозиторію, а не надіслані ванільні оригінали. Попереднє усунення `gfx/FX/constants.fxh` з активної тестової папки залишається чинним. Описувачі й решту тестової копії для цього етапу міняти не потрібно.

Запустити нову кампанію за Німеччину з тим самим набором DLC й лише тестовим модом. Після запуску зберегти свіжі `error.log`, `game.log` та, у разі повторного вильоту, новий `exception.txt`. Це дасть змогу перевірити виправлення цих помилок окремо від решти несумісностей.
